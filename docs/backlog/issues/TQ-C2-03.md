# [TQ-C2-03] Exposer les parcours du MVP via une API HTTP validée et cohérente en erreurs

- Roadmap Cycle: 2
- Roadmap Position: S9 (position 3 du cycle 2)
- Primary Roadmap Topic: S9 Spring Web (MVC, servlet lifecycle, filters, interceptors, validation, exception mapping, API design)
- Secondary Roadmap Topics: S12 Sécurité applicative (entrées non fiables) ; S19 APIs robustes (contrat affiné plus tard) ; S26 Observabilité (identifiant de corrélation)
- Functional Capability: Voyage, Participants, Propositions, Votes, Itinéraire exposés en HTTP ; parcours 1 à 4 des spécifications
- Nature: FEATURE
- Maturity: `OUTLINE`
- Dependencies: TQ-C2-02
- Context Summary: Le noyau est assemblé et configurable mais inaccessible autrement que par des tests. Les dix écrans du MVP ont besoin d'une API pour créer un voyage, inviter, proposer, voter, décider et construire l'itinéraire.
- Problem Summary: Aucun client ne peut utiliser TripQuest ; les entrées HTTP (dates, prix, emails, fuseaux) ne sont pas validées ; les refus métier du noyau n'ont pas de représentation HTTP cohérente ; personne ne sait tracer une requête à travers filtres, interceptors et contrôleurs.
- Objective: API HTTP couvrant le parcours du MVP terminé, validation des entrées, correspondance stable entre refus métier et réponses d'erreur, identifiant de corrélation par requête, compréhension du cycle de vie d'une requête.
- Expected Outcome: Le parcours « créer → inviter → proposer → voter → clôturer → itinéraire → conflits → finaliser → consulter » est réalisable via HTTP ; une entrée invalide produit une erreur exploitable ; une transition interdite produit un refus cohérent.
- Expected Evidence: Test bout en bout HTTP des parcours 1 à 4 ; tests de validation et de mappage des erreurs ; trace commentée d'une requête dans la chaîne Spring.
- Topics Explicitly Deferred: OpenAPI, versionnement, pagination, clés d'idempotence, Problem Details (TQ-C4-01) ; authentification (TQ-C2-04) ; autorisation (TQ-C2-05).
- Unknowns: `UNKNOWN` conception des ressources (granularité, verbes) ; `UNKNOWN` identité de l'appelant avant TQ-C2-04 (mécanisme temporaire de développement, à ne jamais confondre avec ACCOUNT-04) ; `UNKNOWN` forme de l'UI qui consommera l'API (hors roadmap).

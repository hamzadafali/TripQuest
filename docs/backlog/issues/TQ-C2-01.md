# [TQ-C2-01] Assembler les modules de TripQuest dans un conteneur Spring maîtrisé

- Roadmap Cycle: 2
- Roadmap Position: S7 (position 1 du cycle 2 dans ce backlog)
- Primary Roadmap Topic: S7 Spring Core (IoC, bean lifecycle, scopes, injection, post-processors, application context)
- Secondary Roadmap Topics: S30 Architecture (frontières du monolithe modulaire) ; S25 Stratégie de tests
- Functional Capability: transversale — composition des capacités Voyage, Participants, Propositions, Votes, Itinéraire
- Nature: TECHNICAL ENABLER
- Maturity: `OUTLINE`
- Dependencies: TQ-C1-01, TQ-C1-02, TQ-C1-03
- Context Summary: Fin du cycle 1, TripQuest est un noyau métier Java pur assemblé à la main par le harnais. Pour l'exposer en HTTP puis le persister, il faut une composition explicite des modules et un cycle de vie maîtrisé des composants à état (dépôts en mémoire, harnais).
- Problem Summary: L'assemblage manuel ne passe pas à l'échelle et n'impose aucune frontière entre capacités ; le cycle de vie des composants à état est implicite ; une mauvaise portée de bean sur un composant par voyage produirait un partage d'état involontaire.
- Objective: Un contexte Spring assemble le noyau et ses adaptateurs en mémoire, sans que le domaine dépende de Spring ; chaque portée et chaque étape de cycle de vie utilisée est justifiée par un besoin réel.
- Expected Outcome: L'application démarre, ses modules sont identifiables et leurs dépendances autorisées sont explicites ; les composants à état ont un cycle de vie documenté.
- Expected Evidence: Test de démarrage du contexte ; vérification des règles de dépendance entre modules (outil `UNKNOWN`) ; note expliquant un problème de bean réel rencontré et résolu (ordre, portée, post-processor).
- Topics Explicitly Deferred: Auto-configuration et propriétés (TQ-C2-02), exposition HTTP (TQ-C2-03), transactions et proxies (TQ-C2-06).
- Unknowns: `UNKNOWN` découpage exact des modules ; `UNKNOWN` outillage de frontières (Spring Modulith, ArchUnit ou autre) ; `UNKNOWN` séparation domaine / adaptateurs face aux records immuables.

# [TQ-C4-03] Découpler un flux TripQuest par messagerie asynchrone (enabler à valider)

- Roadmap Cycle: 4
- Roadmap Position: S21 (position 3 du cycle 4)
- Primary Roadmap Topic: S21 Kafka fondamental (broker, topic, partition, offset, consumer group, rebalance, ordering)
- Secondary Roadmap Topics: S10 (décisions émettrices) ; S25 Tests (broker conteneurisé) ; S26 Observabilité
- Functional Capability: `UNKNOWN / TO VALIDATE` — hypothèse candidate : notifications in-app (§7), dont l'échec ne doit pas annuler une décision métier
- Nature: TECHNICAL ENABLER
- Maturity: `OUTLINE`
- Dependencies: TQ-C2-06
- Context Summary: La roadmap impose Kafka. Le MVP n'exige aucune messagerie. Le seul flux candidat est la production de notifications in-app à partir des décisions (nouvelle invitation, vote clôturé, activité sélectionnée, itinéraire finalisé). Une solution en processus (événements applicatifs) pourrait suffire.
- Problem Summary: `UNKNOWN / TO VALIDATE`. Le problème à démontrer serait : les effets secondaires d'une décision (notifier plusieurs participants) ralentissent ou font échouer la décision elle-même, et doivent être traités hors de la transaction de décision, dans l'ordre par voyage.
- Objective: Au début du ticket, valider avec un humain que le flux candidat justifie une messagerie plutôt qu'une solution en processus. Si oui, introduire un broker local, un premier topic, un groupe de consommateurs, et démontrer partitionnement, ordre par clé et rebalance. Sinon, ticket technique équivalent sur décision humaine.
- Expected Outcome: Si validé : un flux TripQuest est produit et consommé de façon asynchrone avec un ordre garanti par voyage ; un rebalance est observé et expliqué. Ce n'est pas une décision architecturale approuvée.
- Expected Evidence: Broker local ; topic et consommateurs ; rebalance provoqué et analysé ; ordre par clé démontré ; ou décision humaine documentée.
- Topics Explicitly Deferred: Contrats d'événements (TQ-C4-04), garanties de traitement (TQ-C4-05), cohérence base/messagerie (TQ-C4-06).
- Unknowns: `UNKNOWN / TO VALIDATE` besoin ; `UNKNOWN` alternative en processus ; `UNKNOWN` clé de partition (le voyage est le candidat naturel) ; `UNKNOWN` exécution locale du broker.

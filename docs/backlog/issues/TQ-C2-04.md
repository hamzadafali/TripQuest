# [TQ-C2-04] Authentifier les utilisateurs de TripQuest via un fournisseur OIDC et lier leur compte

- Roadmap Cycle: 2
- Roadmap Position: S11 (position 4 du cycle 2)
- Primary Roadmap Topic: S11 Authentication (Spring Security, filter chain, OAuth2, OIDC, JWT, sessions, resource server)
- Secondary Roadmap Topics: S12 Autorisation ; S20 Clients HTTP résilients (appels au fournisseur d'identité) ; S25 Tests
- Functional Capability: Module A — Comptes et accès (créer un compte, se connecter, profil, nom d'affichage, « mes voyages »)
- Nature: SECURITY
- Maturity: `OUTLINE`
- Dependencies: TQ-C2-03
- Context Summary: L'API expose les parcours du MVP mais l'identité de l'appelant est fournie par un mécanisme de développement. La règle ACCOUNT-04 interdit de déterminer l'identité à partir d'un identifiant librement fourni par le client.
- Problem Summary: N'importe quel client peut se faire passer pour n'importe quel utilisateur ; aucun compte n'existe ; l'unicité de l'adresse email (ACCOUNT-01) n'est pas garantie ; un visiteur non authentifié ne doit rien voir du voyage.
- Objective: TripQuest devient un resource server OIDC ; l'identité est dérivée exclusivement du jeton ; un compte est créé ou lié lors de la première authentification ; le tableau de bord « mes voyages » ne montre que les voyages de l'utilisateur (ACCOUNT-02).
- Expected Outcome: Sans jeton valide, toute ressource privée est refusée ; avec jeton, l'utilisateur agit sous sa propre identité ; deux comptes ne partagent jamais une adresse email.
- Expected Evidence: Resource server configuré contre un fournisseur local ; tests 401 / identité dérivée du jeton / unicité email ; description de la chaîne de filtres et de la décision sessions vs sans état.
- Topics Explicitly Deferred: Autorisation métier, CORS, CSRF (TQ-C2-05) ; résilience des appels au fournisseur (TQ-C4-02) ; envoi d'emails.
- Unknowns: `UNKNOWN` fournisseur OIDC de développement ; `UNKNOWN` source du nom d'affichage (jeton ou saisie) ; `UNKNOWN` sessions vs sans état, qui conditionne CSRF ; `UNKNOWN` rapprochement d'une invitation par email avec un compte dont l'email diffère.

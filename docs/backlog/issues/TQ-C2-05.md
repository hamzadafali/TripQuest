# [TQ-C2-05] Isoler chaque voyage : autorisations par rôle et par appartenance, durcissement applicatif

- Roadmap Cycle: 2
- Roadmap Position: S12 (position 5 du cycle 2)
- Primary Roadmap Topic: S12 Authorization et sécurité applicative (RBAC/ABAC, method security, ownership, CORS, CSRF, SSRF, secrets, OWASP)
- Secondary Roadmap Topics: S9 Spring Web ; S25 Tests ; S27 CI/CD (scans)
- Functional Capability: confidentialité (§9), rôles organisateur / participant / visiteur (§3), propriété des propositions (ACTIVITY-05), invitations (ACCOUNT-03)
- Nature: SECURITY
- Maturity: `OUTLINE`
- Dependencies: TQ-C2-04
- Context Summary: Les utilisateurs sont authentifiés mais rien n'empêche un utilisateur authentifié d'agir sur un voyage dont il n'est pas membre, ni un participant d'exercer une action réservée à l'organisateur via l'API. AC-2 du MVP exige qu'un non-membre ne puisse ni consulter ni modifier un voyage même en connaissant son identifiant.
- Problem Summary: Les règles de rôle existent dans le noyau mais l'API ne vérifie pas l'appartenance ni la propriété avant d'atteindre le noyau ; le lien externe d'une activité pourrait déclencher une requête sortante (SSRF) ; CORS et CSRF ne sont pas définis ; les secrets de configuration n'ont pas de politique.
- Objective: Autorisation par appartenance au voyage et par rôle, vérification de propriété pour les propositions, politique CORS/CSRF cohérente avec TQ-C2-04, aucun accès sortant déclenché par un lien fourni, secrets hors dépôt, threat model simple du MVP.
- Expected Outcome: La matrice « visiteur / participant / organisateur / non-membre × chaque action » est appliquée et testée ; une notification ne confère aucune autorisation (§7).
- Expected Evidence: Matrice de tests d'autorisation ; threat model écrit ; test SSRF ; vérification d'absence de secrets dans le dépôt ; revue des points OWASP pertinents.
- Topics Explicitly Deferred: Limitation de débit (`UNKNOWN`) ; scans automatisés en pipeline (TQ-C5-03).
- Unknowns: `UNKNOWN` droits exacts du coorganisateur (hérité de TQ-C1-01) ; `UNKNOWN` politique CORS liée à une UI non planifiée ; `UNKNOWN` mécanisme de vérification (annotations, filtre, service dédié) à décider à l'analyse.

# [TQ-C4-04] Définir et faire évoluer les contrats d'événements de TripQuest (enabler à valider)

- Roadmap Cycle: 4
- Roadmap Position: S22 (position 4 du cycle 4)
- Primary Roadmap Topic: S22 Contrats événementiels (domain/integration events, schemas, compatibilité, partition keys)
- Secondary Roadmap Topics: S10 (faits métier émis par les décisions) ; S19 (versionnement de contrat) ; S12 (données exposées dans les événements)
- Functional Capability: `UNKNOWN / TO VALIDATE` — dépend de TQ-C4-03 ; candidat : événements de décision (invitation créée, vote clôturé, activité sélectionnée/rejetée, itinéraire finalisé/rouvert)
- Nature: TECHNICAL ENABLER
- Maturity: `OUTLINE`
- Dependencies: TQ-C4-03
- Context Summary: Si un flux asynchrone existe, ses messages deviennent un contrat entre producteur et consommateurs, distinct des faits métier internes du noyau.
- Problem Summary: `UNKNOWN / TO VALIDATE`. Sans distinction entre événements internes et événements d'intégration, toute évolution du noyau casse les consommateurs ; sans schéma ni règle de compatibilité, un champ renommé ou supprimé provoque des échecs silencieux ; une mauvaise clé de partition perd l'ordre par voyage.
- Objective: Si TQ-C4-03 est validé : distinguer événements internes et d'intégration, définir les schémas, les règles de compatibilité et la clé de partition, puis démontrer une évolution de contrat sans casser un consommateur existant.
- Expected Outcome: Si validé : un consommateur de l'ancienne version continue de fonctionner après évolution du contrat. Ce n'est pas une décision architecturale approuvée.
- Expected Evidence: Schémas versionnés ; test de compatibilité ; choix de clé tracé ; ou décision humaine documentée.
- Topics Explicitly Deferred: Reprise et doublons (TQ-C4-05).
- Unknowns: `UNKNOWN` format et registre de schémas ; `UNKNOWN` données personnelles admissibles dans un événement (emails d'invitation) ; `UNKNOWN` devenir si TQ-C4-03 n'est pas validé.

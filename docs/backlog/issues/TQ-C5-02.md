# [TQ-C5-02] Rendre chaque requête et chaque décision de TripQuest observable (logs, métriques, traces)

- Roadmap Cycle: 5
- Roadmap Position: S26 (position 2 du cycle 5)
- Primary Roadmap Topic: S26 Observabilité (logs structurés, Micrometer, Prometheus, traces, OpenTelemetry, correlation IDs)
- Secondary Roadmap Topics: S4 Profiling (baseline de TQ-C1-03) ; S9 (identifiant de corrélation) ; S15 (temps de requête) ; S28 (probes)
- Functional Capability: transversale — traçabilité technique ; indicateurs produit (§11 : voyages finalisés, participants actifs, propositions, conflits détectés)
- Nature: OPERATIONS
- Maturity: `OUTLINE`
- Dependencies: TQ-C2-03, TQ-C1-03
- Context Summary: TripQuest tourne avec HTTP, base et éventuellement messagerie ; le diagnostic du cycle 1 couvre la JVM mais rien ne relie une requête, sa transaction, ses requêtes SQL et ses effets asynchrones.
- Problem Summary: Impossible de suivre une décision de bout en bout ; logs non structurés et non corrélés ; aucune métrique métier ni technique ; les indicateurs produit du §11 ne sont pas mesurables.
- Objective: Identifiant de corrélation propagé partout, logs structurés, métriques techniques et métier exposées, traces distribuées, tableau de bord local.
- Expected Outcome: À partir d'un identifiant, on retrouve la requête, ses logs, sa trace et ses effets ; les indicateurs produit sont lisibles sur un tableau de bord.
- Expected Evidence: Corrélation démontrée de bout en bout ; métriques exposées ; trace complète d'une décision ; tableau de bord local ; indicateurs §11 calculés.
- Topics Explicitly Deferred: Alerting en production (`UNKNOWN`).
- Unknowns: `UNKNOWN` pile locale de collecte ; `UNKNOWN` indicateurs §11 retenus ; `UNKNOWN` données personnelles dans les logs.
